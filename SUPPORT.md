# Support

## Before opening an issue

1. Read the [README](README.md), [format documentation](docs/FORMAT.md), and [standards mapping](docs/STANDARDS-MAPPING.md).
2. Confirm the behaviour on the latest release or `main`.
3. Run `npm run check` and the smallest relevant command or fixture.
4. Remove credentials, private prompts, customer data, model artifacts and dataset contents from logs or examples.

## Bug reports

Use the bug report form and include:

- version or commit;
- affected interface: CLI, library, GitHub Action, schema, discovery or export;
- operating system and Node.js version;
- minimal synthetic reproduction;
- expected and observed behaviour.

## Feature requests

Use the feature request form. Describe the operational question the capability must answer, the evidence available to support it, and any privacy or compatibility constraints.

## Security

Do not open a public issue for a vulnerability. Follow [SECURITY.md](SECURITY.md).

## Support level

The latest release receives best-effort security and critical correctness fixes. This project does not include a commercial support commitment, hosted service or uptime SLA.
